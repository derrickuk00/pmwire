## 一、事實背景（已核實）

### Polymarket 喺英國係被封嘅

- **狀態：close-only。** 英國 IP 可以平倉，唔可以開新倉。純粹靠 IP 偵測封鎖。
- **Gambling Commission 立場：** 將預測市場歸類為需要牌照嘅 betting exchange，
  已警告無牌營運者確保「唔會針對或同英國消費者交易」。
- **FCA 立場：** 兩條線 ——（1）2019 年零售二元期權禁令，Polymarket 合約被歸入二元期權；
  （2）加密資產規例（2027年10月25日生效）。
- **短期唔會變：** 冇跡象顯示 Polymarket 申請緊英國牌照。

### 對你嘅實際意義

| 你做嘅嘢 | 狀態 |
|---|---|
| 喺英國用 Polymarket 落注 | ❌ 你根本做唔到（IP 封鎖），亦唔應該試 |

| 放 referral / affiliate 連結 | ❌ **紅線** |

## 二、真正嘅法律風險：FSMA s.21 財務推廣

英國《2000年金融服務及市場法》第 21 條（Financial Services and Markets Act 2000, s.21）
規定：**喺營業過程中發出「投資活動邀請或引誘」（invitation or inducement to engage in
investment activity），除非你獲授權，或者內容由獲授權人士批准，否則係刑事罪行。**

呢條嘅重點喺「**邀請或引誘**」四個字，唔喺「你有冇賺到錢」。

### 界線喺邊

| ✅ 安全（描述） | ❌ 危險（引誘） |
|---|---|
| 「賠率六小時內由 34% 升到 47%」 | 「呢個價位有值博率」 |
| 「盤口薄，小額資金就推得郁」 | 「而家入場成本低」 |
| 「同期有兩則消息，未確認為成因」 | 「消息未反映喺價格，機會嚟啦」 |
| 「若 X 發生，呢個解讀就唔成立」 | 「等 X 發生就係時候行動」 |
| 「成交額 120 萬美元」 | 「跟我落注」／任何 referral 連結 |

一句話總結：**講「發生咗咩」安全，講「你應該點做」危險。**

### 三個額外要注意嘅位

1. **「唔提供建議」唔可以淨係口頭講，要做到。** 免責聲明唔會救一篇實質上係推薦嘅文。
   監管睇實質內容，唔係睇免責聲明。
2. **Referral / affiliate 連結係最清晰嘅越界。** 一有連結，你由「評論者」變成
   「為報酬招攬客戶」。**呢個系統設計上永遠唔會放連結**（同時亦慳返 X API 每篇
   $0.20 vs $0.015 嘅差價 —— 合規同慳錢碰啱同一個方向）。
3. **廣東話/中文內容一樣受管。** 用中文寫唔會避開英國法。中文禁語清單同英文一樣嚴。

## 三、呢個系統點樣結構性地守住紅線

**唔靠 LLM 記得聽話。LLM 會唔聽指示，正則表達式唔會。**

```
LLM 生成 ──► guard.py 硬掃描 ──► 唔過就帶住原因重寫（最多 3 次）
                  │
                  ├─ 第一層 硬拒絕：64 個字眼（英 37 + 中 27）
                  │   全部係「勸人做嘢」句式，冇合法描述用法
                  │   命中 = 草稿即刻打回，你永遠見唔到
                  │
                  ├─ 結構檢查：免責聲明必須在、URL 一律禁、長度上限
                  │   第二人稱祈使句偵測（you should / must / need to）
                  │
                  └─ 第二層 標記：20 個有歧義嘅字（buy/sell/機會/低估…）
                      唔自動拒絕，但喺 Telegram 審批訊息度標出嚟
                      叫你用眼睇清楚上下文
                            │
                            ▼
                   你人手審批 ──► 撳批准先出街
```

**四道防線，任何一道都可以獨立擋住問題：**

1. **Prompt 層** — system prompt 明文禁止建議語言、禁止斷言成因
2. **Code 層** — 硬編碼掃描，唔理 LLM 講咩
3. **結構層** — 免責聲明強制附加（由 code 加，唔靠 LLM）、URL 永久禁止
4. **人手層** — 你係最後一關，而且你會見到「待留意字眼」標記

### 為何要求「成因一律標記為假設」

呢個唔止係合規，係誠實問題。**賠率郁咗，真正原因通常無法從賠率數據推斷。**
斷言成因就係編故事。系統強制寫成「同期發生咗 X，未確認為成因」，
再加「睇到 Y 就知呢個解讀啱定錯」。

呢個做法有三個好處：
- 合規（唔係引誘，係觀察）
- 誠實（你冇假裝知道你唔知嘅嘢）
- **內容更有價值**（可證偽嘅解讀 > 講故事）

## 四、你自己要守嘅規矩（系統管唔到）

系統管到內容，管唔到你個人行為。以下要你自己守：

- [ ] **Bio 唔好放 Polymarket referral 連結。** 放個人網站或者 newsletter 可以。
- [ ] **回覆讀者時唔好畀意見。** 有人問「你覺得呢個抵唔抵注」，答「我唔畀意見，
      我只做數據描述」。呢個係你最容易失守嘅位。
- [ ] **唔好接 Polymarket 或任何無牌博彩/交易平台嘅贊助。** 呢個直接令你變成
      為報酬招攬。
- [ ] **唔好講自己嘅倉位。** 「我自己揸緊呢個」= 隱含推薦。
- [ ] **如果將來想收費（付費報告）**，先搵律師。收費會改變你嘅法律定位。
- [ ] **保留記錄。** queue.json 同 posted.json 就係你嘅發文記錄，
      GitHub 有完整 git 歷史，出事時證明得到你發過咩。

## 六、如果你想收窄風險到接近零

三個選項，成本由低到高：

1. **加強免責聲明位置** — 而家喺文末。可以改為文首。
   （改 `draft.py` 嘅 system prompt 同 `guard.py` 嘅結構檢查即可。）
2. **明文聲明非英國受眾** — bio 加「Not intended for UK residents」。
   ⚠️ 呢個嘅法律效力有限，而且會影響觸及，我唔特別推薦。
3. **搵律師睇一次** — 英國金融推廣規例專長。一次性費用，
   如果呢個項目有機會做大就值得。
